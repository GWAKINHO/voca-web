## 2. 범위

- **이번 명세서 대상**: 기본 요건 전부 (FR-001~004, 011~014, 021~026, 031~034, NFR-001~005, SUB 전부)
- **이번 범위 밖**: 도전 요건 (FR-041~043, 051~053, 061~062). 명세서에는 ID만 두고 "보류"로 표시한다.
- **제출 요건 SUB-011·016**: 수업 배포본 방법론 사본(SUB-011)은 파일이 없어서 보류. UI/UX·테스트 정의서(SUB-016)는 도전이라 이번 범위 밖.

## 3. 요구사항 분석 (기본)

| ID | 요구사항 (요약) | 분석 결과 | 구현 단위 (예정) |
|---|---|---|---|
| VOCA-FR-001 | 단어 직접 입력 등록 | 영단어 필수, 뜻 필수. 빈 값 거절 | 등록 폼 + `POST /words` |
| VOCA-FR-002 | 목록 조회, 수정·삭제 | 목록 페이지, 수정·삭제 시 이력 처리 필요 (§4 결정 D-3) | `GET /words`, 수정·삭제 라우트 |

| VOCA-FR-004 | 영단어 또는 뜻으로 검색 | 부분 일치 검색 (대소문자 무시) | `GET /words?q=` |
| VOCA-FR-011 | 하루 학습량에 따라 일차 배정 | 하루 학습량 고정값 (§4 D-4). 일차 번호는 `plan` 테이블에 저장 | 진도 배정 함수 |
| VOCA-FR-012 | 한 장씩 영단어 → 뜻 보기 | 카드 한 장 = 한 단어. 뜻 보기 버튼 | 암기 페이지 |
| VOCA-FR-013 | 전날 외운 단어 일부 + 자주 틀린 단어 섞기 | 복습 규칙 (§4 D-5) | 복습 선택 함수 |
| VOCA-FR-014 | 암기 이력 DB 저장 | `study_log` 테이블 | 암기 기록 저장 |
| VOCA-FR-021 | 문제 수 지정 후 그 수만큼 출제 | 문제 수 입력, 단어 수보다 크면 가능한 만큼 출제 후 안내 | 시험 생성 라우트 |
| VOCA-FR-022 | 가중치 출제 | 가중치 규칙 (§4 D-6) | 출제 함수 |
| VOCA-FR-023 | 출제 방향 선택 | 영→한, 한→영, 섞기 | 시험 설정 폼 |
| VOCA-FR-024 | 출제 형식 2종 이상 | 단답형 + 4지선다 (§4 D-2) | 채점 함수 2종 |
| VOCA-FR-025 | 점수, 틀린 문항과 정답 표시 | 제출 후 일괄 표시 | 결과 페이지 |
| VOCA-FR-026 | 시험 이력 문항 단위 DB 저장 | `exam_item` 테이블 (단어, 형식, 방향, 정오, 시각) | 시험 제출 시 저장 |
| VOCA-FR-031 | 현재 일차, 암기 수 / 전체 | `plan`, `study_log`에서 계산 | 통계 함수 |

## 4. 분석 중 결정 (D-번호)

| 번호 | 주제 | 배경 | 대안 | 결정 근거 |
|---|---|---|---|---|
| D-1 | CSV 중복 처리 | 2,000행 파일에 같은 영단어가 있을 수 있음 | (a) 뒤 행으로 덮어쓰기 (b) 건너뛰기 (c) 뜻을 합치기 | **(b) 건너뛰기**. 대소문자와 앞뒤 공백을 무시하고 같은 영단어는 처음 행만 쓴다. 건너뛴 행 수를 결과 화면에 보여 준다. 덮어쓰면 이력과 뜻이 바뀌어 추적이 어렵다 |
| D-2 | 출제 형식 | FR-024는 2종 이상 요구 | 단답형, 4지선다, OX 중 2종 또는 3종 | **단답형 + 4지선다**. 두 형식이면 채점 함수와 보기 생성이 단순하다. OX는 시간이 남으면 추가 |
| D-3 | 단어 수정·삭제와 이력 | 삭제된 단어의 암기·시험 이력이 남으면 통계가 깨짐 | (a) 이력도 함께 삭제 (b) 이력 유지, 단어만 숨김 (c) 삭제 금지 | **(a) 이력도 함께 삭제**. 학습 앱에서 단어가 사라지면 이력도 의미가 없다. 삭제 전 확인 창을 띄운다 |
| D-4 | 하루 학습량 | FR-011은 필요, 설정 저장은 도전 | 고정값 / 입력 칸 / 설정 화면 | **고정값 10개**. 설정 화면은 도전(FR-061)으로 미룬다. 상수 `DAILY_COUNT = 10` 하나로 바꿀 수 있게 둔다 |
| D-5 | 복습 규칙 | FR-013 요구 | 비율 고정 / 개수 고정 | **개수 고정**. 전날 단어 중 최대 5개, 자주 틀린 단어 최대 3개를 그날 목록에 더한다. 자주 틀린 단어는 최근 시험에서 오답 2회 이상인 단어 중 오답 많은 순 |
| D-6 | 가중치 출제 | FR-022: 안 본 단어, 오래된 단어, 자주 틀린 단어가 더 많이 나와야 함 | 단순 무작위 / 가중치 | **가중치 점수**. 한 번도 시험 안 본 단어 +3, 마지막 시험 후 7일 이상 +2, 오답률 50% 이상 +2. 점수를 가중치로 삼아 무작위 추출(중복 없음)한다 |
| D-7 | 자주 틀린 단어 목록 | FR-033의 N | 5 / 10 / 사용자 입력 | **N = 10 고정**. 입력은 도전 설정으로 미룬다 |
| D-8 | 날짜 기준 | 일차와 "전날"은 날짜 경계가 필요 | UTC / 서버 로컬 / 한국 시간 고정 | **한국 시간(Asia/Seoul) 기준으로 날짜를 계산**한다. 컨테이너는 UTC라서 시간대를 명시한다 |
| D-9 | 계정 | 로그인은 도전 | 지금부터 user_id 컬럼 추가 / 나중에 추가 | **지금은 user_id 없음**. 도전 때 `user_id` 컬럼을 추가하고 기존 데이터는 기본 계정에 붙인다 |
| D-10 | 시험 방향과 채점 | FR-023, FR-025 | 대소문자 구분 / 무시 | **대소문자와 앞뒤 공백 무시**. 단답형은 뜻 여러 개 중 하나만 맞아도 정답으로 본다 (쉼표로 나눈 뜻 기준) |

## 5. 데이터 개요 (데이터 설계서에서 확정)

| 테이블 | 주요 열 | 목적 |
|---|---|---|
| `words` | id, en, ko, created_at | 단어 목록. en 은 소문자 정규화 값으로 유일 |
| `plan` | word_id, day_no | 일차 배정 (VOCA-FR-011) |
| `study_log` | id, word_id, day_no, studied_at | 암기 이력 (VOCA-FR-014) |
| `exam_attempt` | id, created_at, direction, qtype, total, correct | 시험 1회 (VOCA-FR-032) |
| `exam_item` | id, attempt_id, word_id, qtype, direction, is_correct, answered_at | 문항 이력 (VOCA-FR-026) |
