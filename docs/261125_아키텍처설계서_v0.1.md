# 시스템 아키텍처 설계서 — 단어장 웹 앱

**파일 위치**: `docs/261125_아키텍처설계서_v0.1.md`
**작성일**: 2026-11-25
**버전**: v0.1
**설명**: 요구사항 명세서 v0.1 의 기본 기능을 구현할 구조(계층, 모듈, 라우트, 템플릿, 배포 구성)를 정한다. 테이블 상세는 데이터 설계서에서 다룬다.

---

## 1. 설계 원칙

| 원칙 | 내용 | 근거 |
|---|---|---|
| 서버 렌더링 | HTML 은 서버가 만든다. JS `fetch` 로 주소를 호출하지 않고, 링크와 폼만 쓴다 | 배포 조건 R-04 (서버가 주소를 바꿔 쓸 때 `fetch` 변수화 실패 위험 제거) |
| 계층 분리 | 라우트(요청·응답) → 서비스(규칙·계산) → DB 모듈(SQL) | 채점·출제 규칙을 화면 없이 테스트할 수 있게 한다 |
| 표준 라이브러리 우선 | DB 는 `sqlite3`, 날짜는 `datetime`, 출제는 `random` | 의존성을 줄여 이미지 빌드와 점검을 안정시킨다 |
| 상태는 DB 에 | 시험 진행 상태, 오늘 목록은 세션이 아니라 DB 와 URL 로 관리 | 도전(로그인) 전까지 세션을 쓰지 않는다. 2개 worker 에서도 일관된다 |

## 2. 전체 구성

```text
[브라우저]
   │  HTTP (PC 크롬)
   ▼
[학교 서버 nginx]  /2026/voca-<학번>/  →  앱의 /  로 옮김, HTML 의 "/…" 주소 다시 씀
   │
   ▼
[컨테이너 voca-web]  gunicorn 0.0.0.0:8080, workers 2, UID 10001
   │
   ├─ Flask 앱 (app.py: create_app)
   │    ├─ routes/   라우트 (Blueprint 4개)
   │    ├─ services/ 규칙 (단어, 암기, 시험, 통계)
   │    ├─ db.py     sqlite3 연결, 테이블 생성, SQL
   │    └─ templates/ Jinja2 HTML,  static/ CSS
   │
   └─ SQLite 파일  /data/voca.db  (환경변수 DB_PATH, named volume)
```

외부 통신은 없습니다. 실행 중 인터넷이 막혀 있어도 동작합니다 (VOCA-SUB-036).

## 4. 계층별 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| routes | 요청 값 꺼내기, 서비스 호출, 템플릿 또는 `redirect` 로 응답 | SQL 쓰기, 채점 규칙 |
| services | 규칙 (정규화, 배정, 가중치, 채점, 집계). 입력은 Python 값, 출력은 dict/list | 요청·응답 객체 사용 |
| db | 연결 열기, 스키마 만들기, SQL 실행 | 규칙 판단 |
| templates | 값 보여 주기, 폼과 링크 | 계산 |

서비스가 `request` 를 모르게 두면 `unittest` 로 규칙을 바로 검사할 수 있습니다.

## 5. 라우트 설계

모든 주소는 `/` 로 시작하는 절대 경로 또는 `url_for` 결과를 씁니다. 호스트 주소는 쓰지 않습니다 (R-04).

| 메서드 | 주소 | Blueprint 함수 | 하는 일 | 응답 |
|---|---|---|---|---|
| GET | `/` | `home.index` | 첫 화면, 메뉴 링크 | HTML |
| GET | `/words` | `words.list_words` | 목록. `?q=` 검색, `?page=` 50개 단위 | HTML |
| POST | `/words` | `words.create_word` | 직접 입력 등록 (FR-001) | redirect `/words` |
| POST | `/words/<int:word_id>/edit` | `words.edit_word` | 수정 (FR-002) | redirect `/words` |
| POST | `/words/<int:word_id>/delete` | `words.delete_word` | 삭제, 이력 함께 삭제, 확인 창은 `onsubmit` 없이 `<details>` 로 (D-3) | redirect `/words` |
| GET | `/words/import` | `words.import_form` | CSV 업로드 폼 | HTML |
| POST | `/words/import` | `words.import_csv` | CSV 읽고 중복 건너뛰기, 결과 표시 (FR-003, D-1) | HTML (결과) |
| GET | `/study?i=<n>&show=<0\|1>` | `study.today` | 오늘 카드를 **한 장씩** 표시. 배정 확인 후 n번째 카드, `show=1` 이면 뜻 표시 (FR-011~013) | HTML |
| POST | `/study/next` | `study.next_card` | 현재 카드를 암기 기록에 남기고 다음 카드로 이동 (FR-014). 기록 일차는 서버가 오늘 기준으로 다시 구한다 | redirect `/study?i=<n+1>` |
| GET | `/exam/new` | `exam.new_form` | 문항 수, 방향, 형식 선택 (FR-021, 023, 024) | HTML |
| POST | `/exam` | `exam.create` | 가중치 출제, 시험 기록 생성 (FR-022, 026) | redirect `/exam/<id>` |
| GET | `/exam/<int:attempt_id>` | `exam.take` | 문제 풀이 폼 | HTML |
| POST | `/exam/<int:attempt_id>/submit` | `exam.submit` | 답 채점, 문항 기록 갱신 (FR-025) | redirect `/exam/<id>/result` |
| GET | `/exam/<int:attempt_id>/result` | `exam.result` | 점수, 틀린 문항과 정답 | HTML |
| GET | `/stats` | `stats.index` | 진도, 정답률 추이, 자주 틀린 단어 10개 (FR-031~034, FR-043) | HTML |
| GET / POST | `/auth/register` | `auth.register_form`, `auth.register` | 회원 가입 및 비밀번호 해시 저장 (FR-041~042) | HTML / redirect `/` |
| GET / POST | `/auth/login` | `auth.login_form`, `auth.login` | 로그인 및 세션 저장 (FR-041) | HTML / redirect `/` |
| POST | `/auth/logout` | `auth.logout` | 로그아웃 (FR-041) | redirect `/` |
| GET | `/ranking` | `ranking.index` | 공개(`is_public=1`) 사용자 학습 진척 순위표 (FR-051~052) | HTML |
| GET | `/ranking/<int:target_user_id>` | `ranking.detail` | 공개 사용자 상세 통계 읽기 전용 조회, 비공개 시 `404` (FR-051~053) | HTML |
| GET / POST | `/settings` | `settings.index`, `settings.save` | 하루 학습량·복습 비율·시험 기본값 설정 저장 (FR-061~062) | HTML / redirect `/settings` |
| POST | `/settings/privacy` | `settings.update_privacy` | 내 통계 공개/비공개 전환 (FR-052) | redirect `/settings` |
| POST | `/settings/reset` | `settings.reset` | 학습·시험 설정 기본값 복원 (FR-061) | redirect `/settings` |
| POST | `/words/reset` | `words.reset_all` | `"전체삭제"` 확인 후 단어장·학습·시험 전체 초기화 (§6.1) | redirect `/words` |

**왜 POST 뒤에 redirect 를 쓰나**: 새로고침으로 같은 요청이 두 번 들어가는 것을 막습니다. 응답 주소는 `/` 로 시작하므로 서버가 `/2026/voca-<학번>/` 아래로 바꿔 줍니다.

## 6. 주요 흐름

### 6.1 암기 (FR-011~014)

```text
GET /study?i=n&show=0|1
  └ study_service.assign_today(conn, today_kst())
      1. study_day 에 오늘 날짜(KST) 행이 없으면 배정 (assign_today)
         - 아직 plan 에 없는 단어를 id 순으로 DAILY_COUNT(10)개 뽑는다 (단어가 0개면 아무것도 하지 않음)
         - study_day 에 다음 day_no 와 오늘 날짜를 넣고, 뽑은 단어를 plan 에 넣는다 (한 트랜잭션)
         - 같은 날 다시 열어도 study_date UNIQUE 때문에 재배정되지 않는다 (데이터 설계서 §4.2)
         - 동시에 두 요청이 배정하면 UNIQUE 충돌을 잡아 먼저 끝난 결과를 쓴다
  └ study_service.build_cards(conn, day_no)
      2. 카드 목록 = 오늘 일차 단어 (id 순)
                    + 직전 일차 단어 중 id 순 최대 5개, 2일차부터 (D-5)
                    + 자주 틀린 단어 최대 3개: 시험 문항 오답 2회 이상, 오답 많은 순 (D-5)
      3. 같은 단어는 한 번만 넣는다
  └ study/today.html: 카드 한 장 (영단어) → [뜻 보기] (GET, show=1) → [다음] (POST)

POST /study/next  (word_id, i)
  └ study_service.record_study(conn, word_id, day_no)   # FR-014
      - 기록 일차는 서버가 오늘 기준으로 다시 구한 day_no (폼 값을 믿지 않음)
      - 없는 단어면 기록하지 않고 넘어간다 (IntegrityError 처리)
  └ redirect /study?i=n+1 (상대 경로)

카드 방식 결정: 목록을 펼치는 방식 대신 한 장씩 보여 준다. 뜻 보기와 다음 넘기기를 서버 요청으로 처리해서 JavaScript 가 필요 없다 (R-04). 기록은 "다음"을 누를 때 남는다 (FR-014 "카드를 넘길 때마다").
```

- "오늘"과 "전날"은 `config.KST` 기준 날짜로 계산합니다 (D-8).
- 배정은 한 번만 합니다. 같은 날 여러 번 열어도 일차가 늘지 않게 `plan` 의 날짜 기록을 확인합니다.

### 6.2 시험 (FR-021~026)

```text
GET /exam/new  → 폼 (문항 수 1~50, 방향 3종, 형식 2종)
POST /exam
  └ exam_service.create_attempt(count, direction, qtypes)
      1. words 전체 로드, 단어마다 가중치 계산 (D-6)
         - 모든 단어 기본 1점
         - exam_item 기록 없음 +3
         - 마지막 시험 후 7일 이상 +2
         - 오답률 50% 이상 +2
      2. 가중치 비례 무작위 추출, 같은 단어 중복 없음 (count 가 단어 수보다 크면 전부)
      3. 문항마다 방향 결정 (섞기일 때 무작위), 형식 결정 (둘 다 선택 시 문항마다 무작위)
      4. 4지선다 문항은 보기 3개를 같은 방향의 다른 단어 뜻으로 채움 (부족하면 단답형으로 바꿈)
      5. exam_attempt 1행, exam_item N행 저장 (답 칸 비움)
  → redirect /exam/<id>

POST /exam/<id>/submit
  └ exam_service.grade(attempt_id, answers)
      - 단답형: 입력값을 소문자·앞뒤 공백 제거 후 뜻 목록(쉼표로 나눈 값)과 비교 (D-10)
      - 4지선다: 선택한 보기 == 정답
      - exam_item.is_correct, answer_given 갱신, exam_attempt.correct, submitted_at 기록
  → redirect /exam/<id>/result
```

- 시험 상태는 DB 의 `submitted_at` 이 비었는지로 판단합니다. 세션을 쓰지 않습니다.
- 이미 제출한 시험은 다시 채점하지 않습니다.

### 6.3 CSV 가져오기 (FR-003, D-1)

```text
POST /words/import   (최대 20MB, Flask MAX_CONTENT_LENGTH)
  └ word_service.import_csv(file_stream)
      1. 파일을 메모리에서 읽기: io.TextIOWrapper(stream, encoding="utf-8-sig")
         (BOM 제거, 디스크에 저장하지 않음)
      2. csv.reader 로 행마다 처리, 첫 행이 "영단어,뜻" 이면 건너뜀
      3. 영단어를 소문자·공백 제거한 값으로 비교, 이미 있으면 건너뜀
      4. 결과: 추가 수, 건너뛴 수, 형식 오류 행 번호 목록
```

### 6.4 통계 (FR-031~034)

- 모든 수치는 `stats_service` 가 DB 에서 계산합니다. 템플릿에는 숫자만 넘깁니다.
- 진도: `MAX(day_no)` 와 `study_log` 의 서로 다른 단어 수 / `words` 전체 수
- 정답률 추이: `exam_attempt` 를 날짜별로 묶어 `correct / total`
- 자주 틀린 단어: `exam_item` 에서 `is_correct = 0` 횟수 순, 상위 10개

## 7. 설정과 환경변수

| 이름 | 기본값 | 쓰는 곳 | 설명 |
|---|---|---|---|
| `DB_PATH` | `/data/voca.db` | `config.py` → `db.py` | SQLite 파일 위치. 개발 PC 에서는 `./data/voca.db` 로 바꿔 씀 |
| `SECRET_KEY` | 없으면 `secrets.token_hex(32)` | `config.py` → `app.py` | 세션용. 현재 세션을 쓰지 않으므로 값이 바뀌어도 기능에 영향 없음 (도전 대비 자리만 둠) |
| `MAX_CONTENT_LENGTH` | 20MB (고정) | `app.py` | CSV 업로드 크기 제한. 서버 기준과 맞춤 |
| `DAILY_COUNT` | 10 (고정 상수) | `config.py` | 하루 학습량 (D-4) |
| `KST` | UTC+9 고정 | `config.py` | 날짜 계산 기준 (D-8). `zoneinfo` 를 쓰지 않는 이유는 §9 참고 |

환경변수는 코드에 기본값을 두되, 비밀이 아닌 값만 기본값으로 둡니다.

## 8. 배포 구성

| 항목 | 설정 | 확인 |
|---|---|---|
| 베이스 이미지 | `python:3.13-slim` | R-02 |
| 사용자 | UID 10001 (`useradd`), 마지막 `USER 10001:10001` | R-05, VOCA-SUB-034 |
| 쓰기 경로 | `/data` (소유자 10001), `/tmp` | R-06 |
| 서버 | `gunicorn --bind 0.0.0.0:8080 --workers 2 app:app` | R-03, R-14 |
| 의존성 | `requirements.txt` 를 먼저 COPY 후 설치 | R-13 |
| 비밀 | `SECRET_KEY` 는 이미지에 없음 | R-08 |
| 점검 | `docker-check.yml` 초록 확인 | VOCA-SUB-037 |

`gunicorn` 2 worker 에서는 같은 DB 파일을 여러 프로세스가 쓰므로, 쓰기 충돌을 줄이기 위해 연결마다 `PRAGMA busy_timeout = 5000` 을 설정합니다. WAL 모드는 `/data` 쓰기 권한 안에서 `-wal` 파일도 만들어지므로 함께 쓰되, 점검에서 문제가 나면 기본 모드로 되돌립니다.

## 9. 설계 결정 (ADR)

| 번호 | 주제 | 배경 | 대안 | 결정 근거 |
|---|---|---|---|---|
| A-1 | 화면 방식 | 과제 권장은 서버 템플릿 + 바닐라 JS | (a) SPA (React/Vue) (b) 서버 렌더링 | **(b)**. 빌드 단계와 `fetch` 주소 문제를 없앤다 (R-04) |
| A-2 | 프레임워크 | 예시와 프롬프트가 Flask 기준 | Flask / FastAPI / Express | **Flask**. 단순하고 Jinja2 가 기본이다 |
| A-3 | DB 접근 | SQLite 만 쓴다 | (a) SQLAlchemy (b) sqlite3 직접 사용 | **(b)**. 의존성이 적고 SQL 을 눈으로 확인할 수 있다 |
| A-4 | 계층 | 규칙 검사를 화면 없이 하고 싶음 | 라우트에 규칙 넣기 / 서비스 분리 | **서비스 분리** (§4) |
| A-5 | 시험 상태 | 세션 없이 여러 요청에 걸쳐 시험 유지 | (a) 세션 쿠키 (b) DB 에 기록 | **(b)**. 새로고침과 여러 worker 에서 안정적이다 |
| A-6 | 시간대 | 컨테이너는 UTC, 날짜 경계는 한국 시간 | (a) `zoneinfo("Asia/Seoul")` (b) 고정 UTC+9 | **(b)**. `python:3.13-slim` 에 시간대 데이터(tzdata)가 있는지 보장되지 않는다. 한국은 일광절약시간이 없어 고정 오프셋이 정확하다 |
| A-7 | CSV 업로드 | 큰 파일을 디스크에 쓰면 `/data` 를 채운다 | 임시 파일 / 메모리 스트림 | **메모리 스트림**. 디스크에 쓰지 않고 20MB 로 제한한다 |
| A-8 | 주소 구조 | 서버가 `/` 아래로 옮김 | 절대 호스트 주소 | **상대 경로만**. `url_for` 또는 `/…` 문자열 (R-04) |
