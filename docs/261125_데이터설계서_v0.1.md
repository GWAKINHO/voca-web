# 데이터 설계서 — 단어장 웹 앱

**파일 위치**: `docs/261125_데이터설계서_v0.1.md`
**작성일**: 2026-11-25
**버전**: v0.1
**설명**: SQLite 테이블의 열, 타입, 키, 제약, 인덱스와 데이터 생명주기를 정의한다. 요구사항 명세서 v0.1 §5 의 개요를 상세화하고, 아키텍처 설계서 v0.1 §6 의 흐름을 뒷받침한다.

---

## 1. 설계 원칙

| 원칙 | 내용 |
|---|---|
| 정규화 | 단어 원본은 `words` 한 곳에만 둔다. 시험 문항은 당시 값을 스냅샷으로 저장한다 (§5.2) |
| 시간 표기 | 모든 시각은 ISO 8601 문자열 + 오프셋 `+09:00` (한국 시간). 날짜 경계는 이 값으로 계산한다 (D-8) |
| 식별자 | 정수 `id` (SQLite 가 자동 증가). 외부에 노출하는 값이 없으므로 UUID 를 쓰지 않는다 |
| 삭제 | 단어 삭제 시 배정과 암기 기록은 지우고, 시험 문항은 남기되 단어 연결만 끊는다 (D-3 보완, §6). 전체 초기화는 §6.1 |
| 스키마 변경 | `PRAGMA user_version` 으로 버전을 기록한다. 현재 버전은 3 (v1/v2 → v3 자동 마이그레이션 지원) |
| 계정 분리 | `users` 테이블과 `user_id` 컬럼으로 계정별 암기·시험·통계·설정을 분리한다. 비로그인 게스트는 `user_id = 0` 을 사용한다 (FR-041~043, FR-062) |

## 2. 테이블 목록

| 테이블 | 역할 | 요구사항 |
|---|---|---|
| `users` | 사용자 계정, 비밀번호 해시, 통계 공개 여부 | FR-041~043, FR-051~052 |
| `words` | 공용 단어 목록 | FR-001~004 |
| `study_day` | 사용자별 날짜와 일차의 대응 (`(user_id, day_no)` PK) | FR-011, FR-043 |
| `plan` | 사용자별 단어가 배정된 일차 (`(user_id, word_id)` PK) | FR-011, FR-013, FR-043 |
| `study_log` | 사용자별 암기 카드 기록 | FR-014, FR-031, FR-043 |
| `exam_attempt` | 사용자별 시험 1회 | FR-021, FR-032, FR-043 |
| `exam_item` | 시험 문항 1개 | FR-022, FR-025, FR-026, FR-033 |
| `user_settings` | 사용자별 하루 학습량·복습 비율·시험 기본값 | FR-061~062 |

## 3. 관계

```text
words (1) ──── (0..1) plan (N) ──── (1) study_day
  │
  ├──── (N) study_log
  │
  └──── (N) exam_item (N) ──── (1) exam_attempt
```

- `plan` 과 `words` 는 1:1 입니다. 단어 하나는 한 일차에만 배정됩니다.
- `study_day` 와 `plan` 은 1:N 입니다. 하루에 최대 10개 단어가 배정됩니다 (D-4).
- `exam_item` 은 `words` 를 참조하지만, 문항의 정답과 문제는 생성 시점의 스냅샷으로 저장합니다.

## 4. 테이블 정의

### 4.1 `words` — 단어

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | INTEGER | 기본 키, 자동 증가 | 단어 번호 |
| `en` | TEXT | NOT NULL | 화면에 보여 줄 영단어 (입력 원본, 앞뒤 공백만 제거) |
| `ko` | TEXT | NOT NULL | 뜻. 여러 뜻은 쉼표로 구분 (예: `사과, 능금`) |
| `en_key` | TEXT | NOT NULL, UNIQUE | 중복 판정용. `en` 을 소문자로 바꾸고 앞뒤 공백을 제거한 값 (D-1, D-10) |
| `created_at` | TEXT | NOT NULL | 등록 시각 (+09:00) |

- `en_key` UNIQUE 로 같은 영단어의 중복 등록을 DB 가 막습니다. 서비스 계층의 검사와 함께 이중으로 지킵니다.
- 뜻 여러 개는 `ko` 한 열에 쉼표로 저장합니다. 단답형 채점 때 쉼표로 나누어 비교합니다 (D-10). 별도 테이블로 나누지 않는 이유는 2,000개 규모에서 복잡도 대비 이득이 작기 때문입니다.

### 4.2 `study_day` — 학습 날짜

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `day_no` | INTEGER | 기본 키 | 일차 번호 (1부터 순서대로) |
| `study_date` | TEXT | NOT NULL, UNIQUE | 학습 날짜 `YYYY-MM-DD` (한국 시간) |
| `created_at` | TEXT | NOT NULL | 배정 시각 |

- 같은 날짜에 두 번 배정되지 않도록 `study_date` 를 UNIQUE 로 둡니다.
- 일차는 날짜 순서대로 늘어납니다. 날짜가 비어도 일차 번호는 건너뛰지 않습니다.

### 4.3 `plan` — 일차 배정

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `word_id` | INTEGER | 기본 키, FK → `words.id` ON DELETE CASCADE | 배정된 단어 |
| `day_no` | INTEGER | NOT NULL, FK → `study_day.day_no` | 배정된 일차 |

- 단어 하나는 `word_id` 가 기본 키이므로 한 번만 배정됩니다.
- 새 일차 배정 규칙: `plan` 에 없는 단어를 `words.id` 오름차순으로 최대 10개 뽑아 새 일차로 넣습니다 (D-4).
- 단어가 0개면 새 일차를 만들지 않습니다.

### 4.4 `study_log` — 암기 기록

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | INTEGER | 기본 키, 자동 증가 | 기록 번호 |
| `word_id` | INTEGER | NOT NULL, FK → `words.id` ON DELETE CASCADE | 본 단어 |
| `day_no` | INTEGER | NOT NULL | 기록 당시 일차 (스냅샷) |
| `studied_at` | TEXT | NOT NULL | 카드를 연 시각 (+09:00) |

- 같은 단어를 여러 번 봐도 기록은 여러 행이 됩니다. "암기한 단어 수"는 `word_id` 를 중복 없이 셉니다 (FR-031).
- 인덱스: `word_id`, `day_no`.

### 4.5 `exam_attempt` — 시험 1회

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | INTEGER | 기본 키, 자동 증가 | 시험 번호 |
| `created_at` | TEXT | NOT NULL | 출제 시각 |
| `submitted_at` | TEXT | NULL 허용 | 제출 시각. NULL 이면 진행 중 |
| `direction` | TEXT | NOT NULL, 값 `en_ko` / `ko_en` / `mixed` | 사용자가 고른 방향 |
| `total` | INTEGER | NOT NULL | 실제 출제 문항 수 (요청 수보다 적을 수 있음) |
| `correct` | INTEGER | NULL 허용 | 맞은 문항 수. 제출 전에는 NULL |

- 진행 중 시험은 `submitted_at IS NULL` 로 찾습니다 (A-5). 세션을 쓰지 않습니다.
- 제출된 시험은 다시 채점하지 않습니다. `submitted_at` 이 있으면 제출 화면으로만 보냅니다.

### 4.6 `exam_item` — 시험 문항

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | INTEGER | 기본 키, 자동 증가 | 문항 번호 |
| `attempt_id` | INTEGER | NOT NULL, FK → `exam_attempt.id` ON DELETE CASCADE | 속한 시험 |
| `seq` | INTEGER | NOT NULL | 문항 순서 (1부터) |
| `word_id` | INTEGER | NULL 허용, FK → `words.id` ON DELETE SET NULL | 출제 단어. 단어가 삭제되면 NULL 이 되고 문항은 남는다 (§6, D-3 보완) |
| `qtype` | TEXT | NOT NULL, 값 `short` / `choice` | 단답형 또는 4지선다 (FR-024) |
| `direction` | TEXT | NOT NULL, 값 `en_ko` / `ko_en` | 이 문항의 방향 (`mixed` 는 문항마다 풀어서 저장) |
| `prompt` | TEXT | NOT NULL | 생성 시점에 보여 준 문제 (스냅샷) |
| `expected` | TEXT | NOT NULL | 생성 시점의 정답 뜻 또는 영단어 (스냅샷) |
| `choices` | TEXT | NULL 허용 | 4지선다 보기 4개를 JSON 배열 문자열로 저장. 단답형은 NULL |
| `answer_given` | TEXT | NULL 허용 | 사용자가 입력하거나 고른 값. 제출 전 NULL |
| `is_correct` | INTEGER | NULL 허용, 값 0 / 1 | 정오. 제출 전 NULL |
| `answered_at` | TEXT | NULL 허용 | 제출 시각 |

제약:
- `(attempt_id, seq)` 는 UNIQUE 입니다. 한 시험에 같은 순서가 두 번 있을 수 없습니다.
- `choices` 는 `qtype = choice` 일 때만 값이 있습니다 (서비스 계층에서 검사).

**스냅샷을 쓰는 이유**: 단어를 수정하면 과거 시험의 정답이 바뀌면 안 됩니다. `expected` 와 `prompt` 를 저장해 두면 통계가 과거 기록을 정확히 보여 줍니다.

**`choices` 를 JSON 으로 저장하는 이유**: 보기는 항상 4개이고 다른 곳에서 검색하지 않습니다. 별도 테이블을 만들면 조인만 늘어납니다. 파이썬 `json` 모듈(표준 라이브러리)로 읽고 씁니다.

### 4.7 `users` — 사용자 계정 (도전, v3 추가)

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | INTEGER | 기본 키, 자동 증가 | 사용자 번호 (`1` 이상, `0`은 비로그인 게스트 예약) |
| `username` | TEXT | NOT NULL | 화면 표시용 아이디 (2~24자) |
| `username_key` | TEXT | NOT NULL, UNIQUE | 대소문자 무시 중복 방지용 소문자 키 |
| `password_hash` | TEXT | NOT NULL | `werkzeug.security` PBKDF2-SHA256 솔트 해시 (평문 저장 금지, FR-042) |
| `is_public` | INTEGER | NOT NULL, DEFAULT 0, 값 0 / 1 | 학습 통계 공개 여부 (`1`: 공개, `0`: 비공개, FR-052) |
| `created_at` | TEXT | NOT NULL | 가입 시각 (+09:00) |

### 4.8 `user_settings` — 학습·시험 설정 (도전, v2 추가)

| 열 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `user_id` | INTEGER | 기본 키 | 사용자 번호 (`0`: 비로그인 게스트, `1+`: 로그인 계정) |
| `daily_count` | INTEGER | NOT NULL, DEFAULT 10 | 하루 학습량 (1~100) |
| `review_ratio` | INTEGER | NOT NULL, DEFAULT 50 | 직전 일차 복습 비율 (0~100%) |
| `review_wrong_count` | INTEGER | NOT NULL, DEFAULT 3 | 자주 틀린 단어 최대 복습 수 (0~20) |
| `exam_count` | INTEGER | NOT NULL, DEFAULT 10 | 시험 기본 문제 수 (1~50) |
| `exam_direction` | TEXT | NOT NULL, DEFAULT `'en_ko'` | 기본 출제 방향 (`en_ko` / `ko_en` / `mixed`) |
| `exam_qtypes` | TEXT | NOT NULL, DEFAULT `'short,choice'` | 기본 출제 형식 쉼표 구분 목록 |
| `updated_at` | TEXT | NOT NULL | 마지막 수정 시각 (+09:00) |

## 5. 값 규칙

### 5.1 정규화

| 대상 | 규칙 | 근거 |
|---|---|---|
| `en_key` | 소문자 변환, 앞뒤 공백 제거 | D-1, D-10 |
| 단답형 정답 비교 | 입력값을 소문자, 앞뒤 공백 제거. 정답 `ko` 를 쉼표로 나눈 각 뜻과 비교 | D-10 |
| 4지선다 정답 비교 | 선택한 보기 문자열이 `expected` 와 같은지 비교 | — |
| CSV `영단어,뜻` 첫 행 | 헤더 행(`영단어,뜻` 또는 `단어,뜻`)이면 건너뜀 | 요구사항 FR-003 |

### 5.2 시간과 날짜

- 저장 형식: `2026-11-25T15:22:00+09:00`
- 날짜 키: `study_date` 는 `2026-11-25`
- 오늘 날짜는 `config.KST` 로 계산한 값입니다 (A-6). 컨테이너의 시간대 설정에 의존하지 않습니다.

## 6. 생명주기와 삭제 규칙

| 이벤트 | 처리 |
|---|---|
| 단어 등록 | `words` 행 추가. 배정은 하지 않음 (배정은 첫 암기 화면을 열 때) |
| 단어 수정 | `en`, `ko`, `en_key` 를 바꿈. 이미 만들어진 `exam_item` 의 스냅샷은 바꾸지 않음 |
| 단어 삭제 | `words` 행 삭제 → `plan`, `study_log` 행은 CASCADE 로 삭제 (D-3). `exam_item` 행은 남기고 `word_id` 만 NULL 로 바꿈 (SET NULL). 문항의 `prompt`, `expected` 스냅샷으로 화면과 정답률은 그대로 유지 |
| 시험 생성 | `exam_attempt` 1행 + `exam_item` N행 추가. 답 칸은 NULL |
| 시험 제출 | 각 `exam_item` 의 `answer_given`, `is_correct`, `answered_at` 갱신, `exam_attempt` 의 `correct`, `submitted_at` 갱신 |
| 전체 초기화 | 아래 §6.1 규칙 (부가 기능, 요구사항 명세서 기본 목록 밖) |

**시험 회차의 삭제된 단어 처리**: 단어를 지워도 `exam_item` 은 남기고 `word_id` 만 NULL 로 바꿉니다. 회차의 `total` 과 `correct` 는 변하지 않으므로 정답률 추이(`correct / total`)가 왜곡되지 않습니다. 회차 상세 화면에는 `prompt` 스냅샷과 "(삭제된 단어)" 표시를 함께 보여 줍니다. 자주 틀린 단어 집계는 `word_id` 가 NULL 인 문항을 제외합니다 (FR-033).

### 6.1 전체 초기화 (부가 기능)

요구사항 명세서의 기본 목록에는 없습니다. 기존 `smart-voca` 에 있던 기능이므로 v0.1 에 포함합니다. 명세서에는 ID 없이 "부가 기능"으로 기록합니다.

| 항목 | 규칙 |
|---|---|
| 지우는 대상 | `exam_item`, `exam_attempt`, `study_log`, `plan`, `study_day`, `words` 전부 |
| 지우지 않는 대상 | `PRAGMA user_version` (스키마 버전), 테이블 구조 |
| 실행 방식 | 한 트랜잭션으로 자식 테이블부터 지운다. 중간에 실패하면 아무것도 지우지 않는다 |
| 확인 방법 | 화면에 "전체삭제" 글자를 직접 입력해야 버튼이 동작한다 (JS 없이 서버에서 검사) |
| 결과 | 단어장과 모든 학습·시험 이력이 사라진다. 되돌릴 수 없음을 화면에 명시한다 |
| 이후 | 빈 DB 상태가 된다. 다음 단어 등록부터 다시 시작한다 |

서버 검사는 `confirm_text == "전체삭제"` 입니다. 이 값이 다르면 아무 것도 지우지 않고 같은 화면에 안내를 띄웁니다.

## 7. 인덱스

| 대상 | 인덱스 | 이유 |
|---|---|---|
| `words.en_key` | UNIQUE (자동 생성) | 중복 검사 |
| `words.ko`, `words.en` | 인덱스 없음 | 검색은 `LIKE` 부분 일치 (2,000행 규모에서 충분) |
| `plan.day_no` | 인덱스 | 일차별 조회 |
| `study_log.word_id` | 인덱스 | 단어별 암기 횟수, 진도 계산 |
| `study_log.day_no` | 인덱스 | 일차별 조회 |
| `exam_item.attempt_id` | 인덱스 | 시험 화면 로드 |
| `exam_item.word_id` | 인덱스 | 단어별 오답률 계산 (FR-022, FR-033) |
| `exam_attempt.submitted_at` | 인덱스 | 진행 중 시험 찾기 |

## 8. 미결 사항

1. **[결정 완료] 삭제된 단어의 시험 회차**: `exam_item.word_id` 를 NULL 허용, `ON DELETE SET NULL` 로 확정했습니다 (§4.6, §6).
2. **아키텍처 설계서 §6.1 보완 (미반영)**: "plan 에 오늘 배정이 없으면" 은 `study_day` 조회로 바꿔야 합니다. 아키텍처 문서는 다음 수정 때 함께 고칩니다.
3. **[결정 완료] 전체 초기화**: 부가 기능으로 포함했습니다 (§6.1). 명세서에는 ID 없이 부가 기능으로 적습니다.
