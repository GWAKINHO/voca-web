# 프로젝트 기획서 — 단어장 웹 앱

**파일 위치**: `docs/261125_기획서_v0.1.md`
**작성일**: 2026-11-25
**버전**: v0.1
**설명**: 단어장 웹 앱(voca-web)의 목적, 범위, 기술 선택, 1차 제출 범위를 정의한다.

---

## 1. 목적

수업 예제인 단어장 프로그램(PyQt·안드로이드, 파일 저장)을 **웹 앱**으로 다시 만든다. 단어를 외우고(암기), 시험으로 확인하고(시험), 학습 진척을 통계로 본다. 이력은 DB에 저장한다. 학교 서버(`/2026/voca-<학번>/`)에 올라가 실행되는 것까지가 과제다.

## 2. 범위

| 구분 | 범위 | 상태 |
|---|---|---|
| 기본 | 단어 등록, 암기, 시험, 학습 진척 통계, 비기능(웹·DB·배포) | 1차 제출 이후 순차 구현 |
| 도전 | 로그인, 다른 계정 이력 보기, 설정 | **이번 단계에서 다루지 않음** |

요구사항 ID와 구현 상태는 `docs/261125_요구사항명세서_v0.1.md` 에서 관리한다. 이번 기획서는 ID 체계와 범위만 정한다.

- 기능: `VOCA-FR-0xx` (기본 001~034, 도전 041~062)
- 비기능: `VOCA-NFR-0xx`
- 제출: `VOCA-SUB-0xx`

## 3. 기술 선택

| 항목 | 선택 | 이유 |
|---|---|---|
| 언어·프레임워크 | Python 3.13 + Flask 3.1.2 | 예시와 Dockerfile 프롬프트가 Flask를 기준으로 하고, 구조가 단순하다 |
| 운영 서버 | gunicorn 23.0.0 (`0.0.0.0:8080`, workers 2) | 공지 R-14: 개발 서버 사용 금지 |
| DB | SQLite (`DB_PATH`, 기본 `/data/voca.db`) | 공지 VOCA-NFR-002. PostgreSQL은 사전 협의 없이 쓰지 않는다 |
| 템플릿 | Flask 기본 Jinja2 (`templates/`) | 서버 렌더링. 바닐라 JS로 충분하다 |
| 배포 | Dockerfile (`python:3.13-slim`, UID 10001) + 점검 워크플로 | 공지 R-01~R-10 |

## 4. 구성 (1차 제출 시점)

| 파일 | 역할 |
|---|---|
| `app.py` | Flask 앱 객체 `app`. `/` 첫 화면 라우트 (`index()`) |
| `templates/index.html` | 첫 화면 템플릿 |
| `requirements.txt` | 실제 쓰는 패키지만 `==` 로 고정 |
| `Dockerfile` | 빌드·실행 규칙 (UID 10001, `/data` 쓰기 권한, gunicorn CMD) |
| `.dockerignore`, `.gitattributes` | 이미지 제외 목록, 줄바꿈 LF 고정 |
| `.github/workflows/docker-check.yml` | 학교 제공 점검 워크플로 (수정하지 않음) |
| `README.md`, `CLAUDE.md` | 앱 소개·실행법, 작업 방식 |

## 5. 1차 제출 기준 (완료 조건)

1. 리포 공개(Public), 루트에 `Dockerfile`
2. `docker-check.yml` 이 제출 커밋에서 **초록**
3. 첫 화면 하나가 `/` 에서 응답
4. 기획서·CLAUDE.md·README가 있고 커밋 이력에 문서와 코드가 함께 쌓임

DB 테이블, 단어 기능은 1차 범위가 아니다. 요구사항 명세서(v0.1)를 먼저 쓰고, 데이터 설계서를 쓴 뒤 구현한다.

## 6. 확인이 필요한 사항 (미정)

- 제공 CSV(2,000개) 파일: 확보 후 VOCA-FR-003 설계에 반영
- 수업 배포본 개발 방법론 사본(VOCA-SUB-011): 확보 후 `docs/`에 추가
- 파일명 규칙: 공지 예시(`기획_yymmdd_제목`)와 수업 방법론 4.2의 `분류_yymmdd_제목` 형식이 우리 방법론(`YYMMDD_문서명`)과 다르다. 채점 기준은 교수님께 확인 필요
